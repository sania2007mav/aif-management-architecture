Конструкционная схема автоматизации управленческого учёта и консолидации: типовая «1С:Бухгалтерия 8.3» остаётся контуром БУ, поверх неё — модуль корректировок, исключения ВГО и отчётности по двум юрлицам.

Вариант размещения

Источник: БП без изменений Управленческий слой Выход: отчётность

Вариант A. Модуль ставится как расширение / подсистема к БП. Пользователь работает в привычном интерфейсе 1С; Excel постепенно уходит из консолидации. Бухгалтерские проводки не переписываются.

Состав модуля и граница с БП

В модуле

  • Регистр упр. корректировокКлассификация без смены БУ
  • Правила ВГОПары контрагентов / договоров / счетов
  • Карта статейБУ → упр. статьи / периоды
  • Контур группыЮЛ-1 + ЮЛ-2, периметр консолидации
  • Отчёты / СКДКонсолидированный P&L, объекты

Остаётся в типовой БП

  • Первичка и проводки по РСБУ
  • Счета учёта, в т.ч. 8110 и себестоимость
  • Аналитика строительных объектов (как есть)
  • Субподрядные договоры как основа себестоимости
  • Закрытие месяца / аудит без вмешательства модуля

Модуль читает БП и пишет только в свои объекты. Аудиторский контур БУ не ломается.

Сравнение вариантов

Приоритет

A · Модуль / расширение в БП

Плюсы: один контур 1С, быстрее MVP, знакомый UI.

Минусы: связанность с обновлениями БП, дисциплина расширения.

Подходит, если организации в одной / связанных базах и команда готова жить в 1С.

Альтернатива

B · Отдельное решение

Плюсы: жёсткая изоляция от БУ, свобода модели данных.

Минусы: интеграция, два контура поддержки, дороже.

Имеет смысл, если базы сильно разведены или нужен независимый продукт.

Не берём в v1: ERP/КА как платформу консолидации и полноценную «строительную» конфигурацию — для группы из двух компаний и текущего объёма прямых затрат это избыточно. Открыты: хранение корректировок, признаки авто-ВГО, косвенные расходы, формы отчётов, оценка трудозатрат.

Черновая конструкционная схема по итогам встречи 08.10.2026. Решение о продукте, бюджете и сроках не принято — страница для обсуждения с разработчиками.
