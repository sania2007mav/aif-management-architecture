# Разработка на 1С (BSL и метаданные)

Дополняет навык **1c-batch** (сборка, выгрузка, загрузка XML). Здесь — только содержательная разработка в коде и метаданных.

## Общие правила BSL

- Ясные имена процедур/функций; избегать «магических» чисел и строк — константы, перечисления, общие модули.
- Ранний выход по условиям вместо глубокой вложенности `Если`.
- Не дублировать запросы в цикле: получить данные пакетом, обойти результат в памяти.
- Транзакции: минимальный объём внутри `НачатьТранзакцию` / `ЗафиксироватьТранзакцию`; при ошибке — `ОтменитьТранзакцию` и проброс или логирование по правилам проекта.
- Пользовательские сообщения — через `НСтр("ru = '...'; en = '...'")` при двуязычии; не хардкодить только русский, если в конфигурации принят мультиязык.

## Запросы

- Указывать нужные поля, избегать `ВЫБРАТЬ *` в производственном коде.
- Индексы и условия в `ГДЕ`/`СОЕДИНЕНИЕ` — осмысленные для СУБД; тяжёлые соединения проверять на объём данных.
- Временные таблицы — когда это упрощает читаемость и план; не плодить без необходимости.

## Сервер / клиент

- Соблюдать границы клиент-серверного вызова: тяжёлая логика и запросы — на сервере; не вызывать с клиента то, что требует привилегированного режима без обоснования.
- Проверять директивы компиляции (`&НаСервере`, `&НаКлиенте` и т.д.) в соответствии с размещением модуля.

## Безопасность и права

- Не обходить RLS и права «в лоб»; привилегированный режим — только в узких общих модулях с явной документацией в коде проекта.
- Внешние обработки/расширения — учитывать ограничения безопасного режима, если они включены.

## Вывод агента

- Предлагать фрагменты BSL в синтаксисе 1С, совместимом с версией платформы, о которой сказал пользователь; если версия не указана — не опираться на устаревший синтаксис без пометки.
- При ссылке на объекты метаданных использовать имена из выгрузки/XML проекта, если они известны из контекста.
